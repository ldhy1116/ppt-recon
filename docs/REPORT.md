# 实验报告：PPT 智能重组工具

## 一、需求分析

**问题**：同一份 PPT 常需面向不同演讲场景（招生宣讲、课堂教学、技术汇报、
答辩、路演等）重复使用，但原稿页序只服务于单一叙事线。人工拖拽重排耗时且
容易破坏章节完整性，还需同步重建目录。

**核心需求**：

1. 读取已有 .pptx，自动识别页面主题与章节结构（不依赖母版/配色）
2. 按用户指定的汇报目的重排**章节顺序**与**章内讲述顺序**，章节成块不打散
3. 支持自然语言交互（轻量智能体）与 CLI 两种入口
4. 输出仍可用 PowerPoint 正常编辑的 .pptx，并可重建目录
5. 普通笔记本可运行：本地小模型 + 低 Token 成本，模型不可用时仍可出结果

**关键约束**：中文 PPT 为主；页数从十几页到上百页；结构形态差异大
（无分标题、「第N节」单层、编号-名称两级体系）。

## 二、总体架构

```
用户自然语言
   │  chat.py（意图解析：3b 模型理解 + Python 严格校验/规则兜底）
   ▼
pptx_reorganize_cli.py（CLI：analyze / reorganize）
   │
   ▼
pptx_reorganize.py（核心库 resolve_order，唯一排序权威）
   ├─ 1. 解析层 analyze_pptx：逐页标题/正文/编号路径/特殊页/稀疏度特征
   ├─ 2. 粗排：小稿(≤30页)全页 LLM；大稿跳过，0-token 关键词序仅作兜底
   ├─ 3. 章节检定升级链：
   │     ⓪ 结构分标题切章(0 token) → ① 标题归组(0 token)
   │     → ② LLM 章节聚类 → ③ 特殊页锚定兜底（前级不可用才升级）
   ├─ 4. 两级编号树 split_top_sections(0 token)：
   │     章内「连续≥2页同号且异于章号」编号段剥离为平级顶层板块
   ├─ 5. 分层目的投票（槽位模板 + Borda 多轮聚合）
   │     板块 3 票 / 章 5 票；温度首轮 0.1、其余 0.15
   ├─ 6. 章内精排：每章独立 LLM（2-24 页窗口，注入 12 目的叙事准则）
   │     漏页按原稿邻接确定性插回；失败回退原序
   ├─ 7. 证据精排（编号归位）→ 特殊页锚定（封面/目录首，总结/参考/致谢尾）
   └─ 8. 输出层：页面物理重排 + 可选删旧目录/插分级目录
```

设计原则：**确定性结构信号优先（0 token）、LLM 只做语义判断、每层失败必有
确定性兜底**，任何一层模型出错都不丢页、不崩溃。

## 三、关键实现

### 3.1 分标题的两种形态识别（0 token）

- 常规形态：编号在标题位（「01」「第2节 线性表」）。纯编号标题需通过
  稀疏度门控（无图表、正文 ≤30 字、≤5 段），避免把带编号的正文页误判为分标题
- 反向形态：名称在标题位、编号为正文首行（「招生政策问答」+「03」），
  严格门控（恰 2 段、正文长度恰为名称+编号长度和），排除
  「招生政策问答 03 常见问题1：报考条件」这类多出一段正文的内容页
- 孤立单页异号数字（如某页正文里的「12」）不满足连续性判据，归为正文

### 3.2 两级编号树

在结构切章结果上检测章尾连续同号段并剥离，使「板块-章」两层各自独立排序；
主板块开篇组（含板块分标题页的引言）恒定板块首位，保证目录上
「板块 → 其章」的父子相邻。板块序失败时按编号升序确定性兜底。

### 3.3 槽位模板投票（章序）

不让模型直接输出排列（3b 极易输出非法排列），而是让模型做
「章 → 叙事槽位」的语义分类，槽序由目的模板强制（如技术汇报：
背景→相关工作→需求→方案→实现→验证→结论）。多轮投票经 Borda 聚合，
吸收单轮怪票；专用槽（封面/目录/参考/致谢）有严格门控，普通章乱塞专用槽
判无效，门控全拒时宽松二次扫描。

欠填治理：prompt 注入章数 N 并要求 slots 恰好 N 项全覆盖；
单轮只要 ≥1 个有效章即采纳，漏章由模板槽秩确定性补全（实测组级失败归零）。

### 3.4 章内精排与邻接补漏

每章 ≤24 页独立调用，准则是「听众视角理解顺畅度」而非讨好目的；
模型漏排的页按原稿邻接插回（最近前邻之后；章首漏页插后邻之前；
连续漏排成链归位），避免漏页被甩到章末破坏语义。

### 3.5 自然语言意图解析

12 种目的的有序关键词规则优先（防止模型联想带偏），其余字段模型解析后
经 Python 枚举校验/归一，任一环节非法即整字段回退规则，保证下游永远拿到
合法结构。支持 reorganize/reorder/toc/analyze 四类意图与
删旧目录/增新目录组合操作。

## 四、测试结果

### 4.1 单元测试

107 项（1 项按环境跳过），覆盖：特殊页识别、分标题两种形态、两级树剥离
与回退、槽位门控与补全、Borda、邻接补漏、目录分级、排列校验等。
`python -m unittest tests.test_reorganize` 全部通过。

### 4.2 端到端用例

| 用例 | 页数 | 形态 | 结构识别结果 |
|------|------|------|-------------|
| test1 | 18 | 研究报告、无分标题 | 标题归组切章 5 章 + 全页 LLM 排序 |
| test2 | 57 | 课件、「第N节」单层 | 开篇 + 4 节，章节成块 |
| test3 | 60 | 招生宣讲、两级编号 | 11 章编号 01-10 + 剥离 2 个平级板块（招生/问答） |

### 4.3 稳定性实测（test3 对应形态的真实长稿，同目的连跑）

- 板块序：连续多次运行保持一致；3 轮/3 轮有效，无回退
- 章序：降温（0.1/0.15）+ 5 票 Borda 后，三次运行差异收窄为两对近义章
  互换（师资/培养、国际/校园），板块层与开篇锚定稳定
- 完整性：每次输出均为 1..N 全排列，无丢页、无重复

## 五、安全措施

1. **无真实敏感数据**：仓库只含合成用例（虚构大学/虚构技术项目），
   真实 PPT 由 .gitignore 强制排除
2. **无真实密钥**：`.env` 忽略入库，提供 `.env.example`；默认值
   `ollama` 仅为本地服务占位；远程 API Key 从不硬编码
3. **本地推理优先**：默认模型本地运行，PPT 内容不出本机；切远程接口
   需用户显式配置
4. **写盘安全**：默认先预览再确认；输出路径校验，拒绝非 .pptx；
   覆盖需 `--force`
5. **输入健壮性**：排列恒经 `normalize_order` 全排列校验；
   LLM 返回的越界章号、重复项、非法槽位全部过滤后确定性兜底

## 六、低 Token / 性能优化

1. **结构前置，0 token 切章**：分标题/编号等显式信号优先，
   长稿无需把几十上百页全文发给模型即可确定章节块
2. **大稿跳过全页 LLM**：>30 页不做全页排序调用，改为
   「章节小粒度投票 + 每章 2-24 页精排」，单次 prompt 短、失败可局部重试
3. **槽位分类替代自由排序**：模型输出空间从 k! 降为每章一个枚举选择，
   3b 即可稳定完成，且输出可严格校验
4. **目的模板固化叙事骨架**：12 套槽位模板 + 关键词/TextRank 兜底，
   模型不可用时整条链路仍 0 token 产出可用结果
5. **多轮投票小温度**：首轮 0.1 定调、后续 0.15 小幅探索，
   板块层仅 3 票、章层 5 票，在稳定性与调用次数间取平衡
6. **失败不重烧**：解析器在同一次响应内做门控→宽松二次扫描→模板补全，
   尽量榨取单次调用的有效信息，减少重试轮次

## 七、局限与后续方向

- 3b 近义章判断仍有小幅跨运行波动；可换 7b 或远程更强模型进一步收敛
- 目录页为文本框重建，不保留原母版样式
- 纯图片/无文本 PPT 退化为锚定 + 原序
- 暂不支持跨章合并/拆页/内容改写，只做页面级重排与目录增删
